# KPI Monitor — Keys for Licensed Sources Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let users store API keys and licence credentials manually (encrypted, write-only), pick one per custom KPI or source, and have the tool send it when fetching (spec §5.10).

**Architecture:**
- A `credentials` table holds Fernet-encrypted secrets. `app/credentials.py` owns the crypto, the `apply()` helper that adds a key to a request, and redaction.
- Watch targets and sources gain a nullable `credential_id`.
- The watch fetch path takes an optional credential: https only, same host only, dropped on cross-host redirects.
- The pipeline gives built-in connectors an httpx client whose event hook adds the source's key to requests aimed at the hosts the connector declares.
- The UI adds a Keys card to Settings and Key dropdowns to the forms.

**Tech Stack:** `cryptography` (Fernet) plus the existing FastAPI/SQLAlchemy/Alembic/httpx backend and the Vue 3 frontend.

**Spec:** `docs/superpowers/specs/2026-11-24-kpi-monitor-design.md` §5.10 (§5.9 for watch targets).

**Base:** branch `feat/keys` from `main` (5b97fbb).

## Global Constraints

- **Key types:**
  - `header` has `header_name` (default `Authorization`) and an optional `prefix`; the header value is `"{prefix} {secret}"` when there is a prefix, otherwise the secret alone.
  - `query` has `param_name`.
  - `basic` has `username` plus the secret as the password.
- **Storage and visibility:**
  - Secrets are encrypted with Fernet keyed by env `KPI_SECRET_KEY`. Accept a urlsafe-base64 32-byte Fernet key; anything else is derived to one with SHA-256.
  - If `KPI_SECRET_KEY` is unset, every key-write endpoint returns 503 `{"detail": "KPI_SECRET_KEY is not set — see README → Keys"}`, and fetches that need a key fail with error `key unavailable (KPI_SECRET_KEY not set)`.
  - Secrets never appear in any API response, log line, `run.error`, snapshot, raw file, preview or Mattermost message. Redaction replaces the secret, and for basic auth also the base64 header, with `***`.
- **Sending:**
  - A key is sent only over https. A target with a key and an http URL is rejected with 422 `{"detail": "keys can only be sent over https"}`.
  - On a redirect to a different host the key is dropped. It is kept on same-host redirects.
  - Keys are not supported with `use_browser`. That combination is rejected with 422 `{"detail": "keys can't be used with \"Needs a browser\" yet"}`.
- **Rejected keys:** an HTTP 401/403 response to a request that carried a key gives target status `key_rejected` with error `key rejected (HTTP 401)` (or 403). It counts as not checked in the `incomplete:` summary.
- **Deleting keys:** deleting a key that is in use returns 409 `{"detail": "key is in use", "used_by": {"targets": [{id, kpi_name, source}], "sources": [slug]}}`.
- **Import:** the optional 4th column is `Key name`, matched case- and space-insensitively like the others. An unknown name makes the row invalid with error `unknown key: {name}`.

## Review Focus

1. **A key could leak through the stored URL.** For a `query` key the secret becomes part of the request URL, which could end up in the raw JSON, `run.error` or the httpx debug logs. Store only the URL without the secret and redact everywhere. Test: Task 2 `test_query_key_not_persisted_anywhere`.
2. **A redirect to another host:** `https://api.a.com` returns a 302 to `https://evil.b.com`. The key must not be sent to b.com. Test: Task 2 `test_key_dropped_on_cross_host_redirect`.
3. **`KPI_SECRET_KEY` is changed after keys were stored.** Decrypting fails, and that must not crash a run. The target errors with `key unavailable (cannot decrypt — was KPI_SECRET_KEY changed?)`, and the Keys page shows the key as "Needs re-entry". Test: Task 1 `test_wrong_secret_key_marks_unreadable`.
4. **Deleting a key that a KPI uses.** Expect 409 with `used_by`, and nothing deleted. Test: Task 1 `test_delete_in_use_409`.
5. **Rotating a key mid-run.** Replacing the secret while a run is in flight must not break it. Runs read the secret when the download starts. Test: Task 3 `test_replace_secret_takes_effect_next_run`.

### Task 1: Key store (crypto, model, API)

**Files:**
- Create: `backend/app/credentials.py`, `backend/app/api/routes_credentials.py`, `backend/migrations/versions/0007_credentials.py`, `backend/tests/test_credentials.py`
- Modify: `backend/app/models.py`, `backend/app/config.py` (`kpi_secret_key: str | None`), `backend/app/api/main.py`, `backend/pyproject.toml` (`cryptography`), `.env.example` (`KPI_SECRET_KEY=` with a comment on how to generate it)

**Interfaces:**
- Produces:
  - Table `credentials`:
    - `id`, `name` (unique, case-insensitive via a unique index on `lower(name)`)
    - `kind` text, `header_name` text null, `prefix` text null, `param_name` text null, `username` text null
    - `secret_enc` bytea, `created_at`, `updated_at`, `last_used_at` null, `last_error` text null
  - Columns `watch_targets.credential_id` and `sources.credential_id`: bigint null, FK to `credentials.id` with ON DELETE RESTRICT.
  - `credentials.py`:
    - `class KeyUnavailable(Exception)`
    - `encrypt(secret: str) -> bytes` and `decrypt(blob: bytes) -> str`. Both raise `KeyUnavailable("KPI_SECRET_KEY not set")` when the env var is unset. `decrypt` raises `KeyUnavailable("cannot decrypt — was KPI_SECRET_KEY changed?")` when the token is invalid.
    - `@dataclass Credential(id, name, kind, header_name, prefix, param_name, username, secret)`
    - `load(session, credential_id) -> Credential`
    - `apply(cred: Credential, url: str, headers: dict) -> tuple[str, dict]` returns the URL with the query parameter added, and headers with the header or basic auth added.
    - `redact(text: str, cred: Credential | None) -> str`
    - `mark_used(session, credential_id, error: str | None)`
  - API, all behind the existing auth:
    - `GET /api/credentials` → `[{id, name, kind, header_name, prefix, param_name, username, has_secret, readable, created_at, updated_at, last_used_at, last_error, used_by: {targets: [...], sources: [...]}}]`
      - `has_secret` is always true.
      - `readable` is false when decryption fails.
      - The secret is never returned.
    - `POST /api/credentials` with `{name, kind, header_name?, prefix?, param_name?, username?, secret}` → 201 item.
      - 409 for a duplicate name.
      - 422 when a field required by `kind` is missing (header needs `header_name`, query needs `param_name`, basic needs `username`) or `secret` is empty.
    - `PATCH /api/credentials/{id}` accepts any field. Sending `secret` replaces it.
    - `DELETE /api/credentials/{id}` → 204, or 409 per Global Constraints.

### Task 2: Send keys when fetching watched pages and API links

**Files:**
- Modify: `backend/app/connectors/watch/fetch.py`, `backend/app/connectors/watch/connector.py`, `backend/app/api/routes_watch.py`, `backend/app/watch_import.py`
- Test: `backend/tests/test_watch_keys.py`

**Interfaces:**
- Consumes: Task 1 `load`, `apply`, `redact`, `mark_used`, `KeyUnavailable`.
- Produces:
  - `fetch_target(client, url, use_browser=False, state=None, credential: Credential | None = None) -> FetchResult`:
    - With a credential: refuse http (`error`, `keys can only be sent over https`), refuse `use_browser` (`error`, as in Global Constraints), and apply the key on every hop whose host equals the original host. On a cross-host hop, fetch without the key.
    - A 401/403 on a hop that carried the key gives `FetchResult("key_rejected", error="key rejected (HTTP 401)")`.
    - Every `error` string goes through `redact`.
  - `WatchConnector.download`:
    - Loads each target's credential, in the same short session, before network I/O.
    - Passes it to `fetch_target`.
    - On `KeyUnavailable`, records the target as `error` with that message.
    - Calls `mark_used` after the run.
    - Stores the target's original URL (without key params) in the raw JSON, never the keyed URL.
  - `parse`: `key_rejected` counts as not checked in the `incomplete:` warning, with its status shown.
  - `routes_watch.py`:
    - Target create, patch and import accept `credential_id`, or `credential_name` in import. Validate https and no browser per Global Constraints.
    - `POST /api/watch-targets/test` accepts `credential_id`.
    - Responses include `credential_id` and `credential_name`.
  - Import: the optional `Key name` column.

### Task 3: Keys for built-in sources

**Files:**
- Modify: `backend/app/connectors/base.py` (optional `credential_hosts: tuple[str, ...] = ()` on the protocol, documented), `backend/app/core/pipeline.py`, `backend/app/api/routes_sources.py`
- Test: `backend/tests/test_source_keys.py`

**Interfaces:**
- Produces:
  - When a source has a `credential_id` and its connector declares `credential_hosts`, `run_source` builds the httpx client with a request event hook. The hook applies the key only to https requests whose host is in `credential_hosts`.
  - The secret is loaded once at the start of the download.
  - If the source has a key but its connector declares no hosts, the run is not affected. `/api/sources` exposes `credential_supported: bool` so the UI can hide the dropdown.
  - `run.error` is redacted. A 401/403 from a keyed host makes the run `failed` with error `key rejected (HTTP 401)`.
  - `PATCH /api/sources/{slug}` accepts `credential_id` (null clears it). `/api/sources` items gain `credential_id`, `credential_name` and `credential_supported`.

**Interfaces:**
- Consumes: the Task 1–3 endpoints.
- Produces:
  - **KeysCard:**
    - A list of keys showing name, type summary (e.g. `Header Authorization: Bearer ••••` / `Link parameter api_key=••••` / `Username alice + password`), "Set ✓" or "Needs re-entry" (warn), last used, last error, and "Used by N".

  - **ImportDialog:** the template becomes `Source name,KPI name,Link,Key name`, and the preview shows a Key column.
  - Secrets are never placed in the URL, a query string, localStorage or logs. The password input is cleared after save.
